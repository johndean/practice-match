# Decision: the design tool's image editor is removed from the shipped `image-slot` (2026-09-05)

**Context.** The approved design's `<image-slot>` element carries an editor — a Replace/Edit strip and a reframe overlay — that exists so images could be placed quickly while designing. It is unpermissioned and gated on a `data-editable` flag the app never sets, so in the product it is dead: invisible, mouse-inert, and without any upload backend. John's zero-gap audit found that the strip is nonetheless keyboard-focusable and announced by assistive technology in every browser (the design's `.ctl{display:flex}` overrides the browser rule that hides closed popovers): 12 phantom tab stops on the Listing screen (WCAG 2.1 SC 2.4.3, 4.1.2). The design has the identical defect.

**Decision (John, 2026-09-05).** Remove the editor chrome from the port now (Platform Task 4e, fix round 3): the `.spill` overlay, the `.ctl` strip and the hidden file input, with their handlers. The design stylesheet stays byte-for-byte; the DOM oracle ignores the design's editor nodes inside an `image-slot` shadow root (rule E). No pixel changes.

**Consequence — backlog item for Wave 2b: Permissioned photo management.** A seller uploads photos for their own listing through the API; every write is gated by the ownership and role checks from the Identity wave (2a); files land in object storage through the adapter the Census plan introduces (A2); images are processed to the sizes the design uses; staff can moderate and remove. This replaces the design tool's editor entirely. The `image-slot` element remains display-only until then.
