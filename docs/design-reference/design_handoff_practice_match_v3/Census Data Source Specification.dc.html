1. Scope and design rules

The market-data layer answers one buyer question — what is the community around this practice like, and who else is already serving it? — from public federal data. It never sources practice financials; those are seller-entered and separately governed.

  1. Pinned vintages. Every request names an explicit year. No endpoint is called without a vintage, and vintages advance only through a migration.
  2. Pre-aggregate, never call at request time. All Census reads happen in scheduled ingest jobs. The web app reads only our own tables.
  3. Derived is labeled derived. Any figure we compute (pet households, drive-time catchments, opportunity score) is stored in a separate column family and rendered with a "derived estimate" qualifier.
  4. Licensing gates production. A dataset with an unresolved license cannot be ingested, cached, or displayed. Enforced by a foreign key to dataset_registry.license_status = 'cleared'.
  5. Degrade, never block. A failed data layer hides itself and logs; listings, search and messaging must stay fully functional.

2b. Choropleth geometry — the basemap does not carry values

The Esri basemap supplies imagery only. It contains no Census attributes and cannot shade anything, so neighbourhood-level shading requires a separate boundary layer drawn over it: one polygon per Census geography, filled by that polygon's own value. Two inputs are needed and both are already cleared in §2.

  1. Geometry — tiger_cb cartographic boundary files, as GeoJSON, one file per metro and per geography level. ZCTA is the recommended default: it is the level buyers think in, and it matches the granularity of the reference design. Tract is available where finer detail is wanted, county for national overviews.
  2. Values — the ACS and CBP tables in §2, joined to geometry on GEOID. Every metric in §4 is already keyed by GEOID, so no new extraction is required.

Implementation notes for the front end:

  • Serve simplified geometry (Douglas–Peucker, ~0.0005° tolerance) and cache per metro. Full-resolution TIGER files are far larger than a map view needs.
  • Render as a Leaflet GeoJSON layer on a canvas renderer, classed on the same breaks the legend publishes. Classed fills, never a continuous gradient.
  • Polygons must be non-overlapping and fully opaque within a class, or overlap compositing will make two mid-class areas read darker than one high-class area and the legend will mislead.
  • Where a geography has no value, render it as an explicit "no data" class — hatched or neutral grey — never as zero.
  • Attribute the geometry vintage alongside the value vintage; TIGER boundaries and ACS releases do not always share a year.
Prototype deviation — must be replaced

The V3 prototype has no boundary file, so it approximates areas with a fine grid in which each cell takes the value of its nearest community centroid (MarketMapV3.jsx, mosaicCells). The cells are contiguous and non-overlapping, which is what a choropleth requires, but their edges are grid artefacts rather than real neighbourhood lines — which is why the prototype reads blockier than the target design. This is spatial assignment of existing data, not interpolation, and no new data is invented. Production must load real polygons; the map component is structured so this is a data swap, not a redesign.

3. Endpoints and authentication

All Census Data API calls share the shape https://api.census.gov/data/{vintage}/{dataset}?get={vars}&for={geo}&in={parent}&key={KEY}. Register a key at api.census.gov/data/key_signup.html; store it in the secret manager as CENSUS_API_KEY. Unkeyed callers are throttled at roughly 500 requests per IP per day, which is below our ingest volume — treat a missing key as a hard startup failure in the ingest worker, never a silent fallback.

Reference calls
ACS tract: /data/2023/acs/acs5?get=NAME,B01003_001E,B01003_001M,B11001_001E,B19013_001E,B19013_001M&for=tract:*&in=state:48+county:453
ACS place: /data/2023/acs/acs5?get=NAME,B01003_001E,B11001_001E,B19013_001E&for=place:*&in=state:48
CBP vet estab: /data/2022/cbp?get=NAME,ESTAB,EMP,PAYANN&for=county:453&in=state:48&NAICS2017=541940
QWI wages: /data/timeseries/qwi/sa?get=EarnBeg,Emp,HirA&for=county:453&in=state:48&year=2024&quarter=4&industry=5419&ownercode=A05&seasonadj=U
Geocode: geocoding.geo.census.gov/geocoder/geographies/address?street=…&city=…&state=TX&benchmark=Public_AR_Current&vintage=Current_Current&format=json

Operational rules: 15-second connect timeout, 45-second read timeout, three retries with exponential backoff and jitter on 5xx and 429 only, no retry on 4xx. Set a descriptive User-Agent naming the VIN Foundation and a contact address. Serialize ingest to at most four concurrent requests per dataset.

6. Geography levels and resolution order

Summary level Geography GEOID shape Role in the product
140Census tract11 digitsPrimary unit. Drive-time catchments aggregate tracts.
150Block group12 digitsOptional refinement; high MOE, off by default
160Place (city/town)7 digitsThe community label shown on anonymized listings
860ZCTA5 digitsFallback when a seller gives ZIP but no address
050County5 digitsOnly level with CBP/QWI industry detail

040State2 digitsBenchmark denominators

Resolution order for a listing: full street address → geocoder returns tract, county, place → tract-level ACS. If the address is missing or fails to match, fall back to ZCTA centroid → containing tract. If that fails, fall back to place, then county, and set geo_precision accordingly. Never silently promote a county figure into a tract-labeled slot; the UI reads geo_precision and changes its wording ("around this community" vs "in this county").

7. Joins and the ingest pipeline

  1. Geocode on listing write. Address → Census Geocoder → (lat, lon, tract_geoid, county_geoid, place_geoid), written to practice_location. Result cached by normalized address hash for 365 days.
  2. Catchment build. For each listing, compute the drive-time polygon (§8), intersect with geo_area.geom at summary level 140 using PostGIS, and store one row per (listing, tract, band) with an area-overlap weight in practice_catchment.
  3. ACS join. practice_catchment ⋈ acs_measure ON geo_id AND vintage. Counts (population, households) are summed with the overlap weight; medians are not summable — take a household-weighted average and flag it as an approximation.
  4. Industry join. practice_location.county_geoid ⋈ cbp_industry ON (geo_id, naics_code, vintage). County granularity only.
  5. Metric materialization. Write one row per (listing, metric, vintage) into market_metric with provenance. The web app reads only this table plus geo_area.
  6. Choropleth tiles. Nightly job renders tract-level vector tiles per metric into object storage, versioned by vintage; the client fetches static tiles, never live geometry queries.

8. Derived fields — exact formulas

Each derived field is stored with is_derived = true and a formula version. Changing a formula requires a version bump so historical values remain explicable.

The opportunity score is an editorial composite chosen by the VIN Foundation, not a market valuation. It must always render alongside its three components so a buyer can see what moved it, and it must never appear in a listing's price context.

12. Licensing and attribution

  • Census Bureau data. Works of the U.S. government are not subject to domestic copyright, so ACS, CBP, QWI, BDS, TIGER and Geocoder output may be used commercially and redistributed. Attribution is requested, not optional for us: every surface carries "Source: U.S. Census Bureau, [dataset], [vintage]". We must not use the Census Bureau's name, seal or logo in any way that implies endorsement or verification of a listing.
  • OpenStreetMap. ODbL 1.0. The credit "© OpenStreetMap contributors © CARTO" must be visible on every map view, with a link to the copyright page. Tiles are served by CARTO rather than the OSM VIN Foundation's volunteer servers, whose tile usage policy prohibits embedded application traffic. Derived database extracts, if we ever produce them, carry share-alike obligations — do not create them without counsel.
  • Satellite imagery. No free-tier imagery is cleared for this use yet. The Satellite toggle stays behind a feature flag until a written license names commercial web display and states the attribution string.
  • Pet-ownership incidence. Commercial survey data is licensed, usually per-seat and non-redistributable. Until a license is signed, ship only the ACS-derived estimate, labeled as derived, with the assumed rate disclosed.
  • Practice location databases. Any purchased or scraped list of veterinary locations is out of scope for V1. Competition counts come from CBP establishment totals only, which carry no third-party rights.
  • Display obligations in code. Attribution strings live in dataset_registry.attribution_text and are rendered from the database, not hard-coded in components, so a terms change propagates in one edit.

13. Database schema

CREATE EXTENSION IF NOT EXISTS postgis;

-- Provenance for every load. Created first: other tables reference it.
CREATE TABLE ingest_run (
  id             bigserial PRIMARY KEY,
  dataset_key    text NOT NULL,
  vintage        text NOT NULL,
  started_at     timestamptz NOT NULL,
  finished_at    timestamptz,
  status         text NOT NULL CHECK (status IN ('running','succeeded','failed','aborted')),
  rows_written   bigint DEFAULT 0,
  request_count  integer DEFAULT 0,
  raw_payload_uri text,
  error_detail   text
);

-- Every external source, and whether it may be used at all.
CREATE TABLE dataset_registry (
  dataset_key      text PRIMARY KEY,
  display_name     text NOT NULL,
  api_dataset_id   text,
  base_url         text NOT NULL,
  vintage          text NOT NULL,
  naics_param      text,
  refresh_cadence  text NOT NULL,
  license_status   text NOT NULL CHECK (license_status IN ('cleared','unresolved','blocked')),
  license_name     text,
  license_url      text,
  attribution_text text NOT NULL,
  last_verified_at timestamptz,
  notes            text
);

-- Census geographies with geometry, one row per GEOID per vintage.
CREATE TABLE geo_area (
  geo_id        text NOT NULL,
  summary_level char(3) NOT NULL,        -- 140 tract, 150 bg, 160 place, 860 zcta, 050 county, 310 cbsa, 040 state
  vintage       text NOT NULL,
  name          text NOT NULL,
  state_fips    char(2),
  county_fips   char(3),
  parent_geo_id text,
  land_area_m2  bigint,
  geom          geometry(MultiPolygon, 4269),
  centroid      geometry(Point, 4269),
  PRIMARY KEY (geo_id, summary_level, vintage)
);
CREATE INDEX geo_area_geom_gix ON geo_area USING gist (geom);
CREATE INDEX geo_area_level_idx ON geo_area (summary_level, vintage);

-- ACS estimates, long format: one row per geography per variable per vintage.
CREATE TABLE acs_measure (
  geo_id        text NOT NULL,
  summary_level char(3) NOT NULL,
  vintage       text NOT NULL,
  variable      text NOT NULL,           -- e.g. B19013_001E
  estimate      numeric,
  moe           numeric,
  ingest_run_id bigint NOT NULL REFERENCES ingest_run(id),
  PRIMARY KEY (geo_id, summary_level, vintage, variable)
);
CREATE INDEX acs_measure_var_idx ON acs_measure (variable, vintage);

-- CBP / AIES industry facts. County granularity.
CREATE TABLE cbp_industry (
  geo_id           text NOT NULL,
  summary_level    char(3) NOT NULL,
  vintage          text NOT NULL,
  naics_code       text NOT NULL,        -- '541940'
  establishments   integer,
  employment       integer,
  annual_payroll_k bigint,
  flag             text,                 -- Census noise/suppression flag, verbatim
  ingest_run_id    bigint NOT NULL REFERENCES ingest_run(id),
  PRIMARY KEY (geo_id, summary_level, vintage, naics_code)
);

-- QWI labor-market series.
CREATE TABLE qwi_measure (
  geo_id               text NOT NULL,
  summary_level        char(3) NOT NULL,
  naics_code           text NOT NULL,    -- '5419'
  year                 smallint NOT NULL,
  quarter              smallint NOT NULL,
  avg_monthly_earnings integer,
  sector_employment    integer,
  sector_hires         integer,
  ingest_run_id        bigint NOT NULL REFERENCES ingest_run(id),
  PRIMARY KEY (geo_id, summary_level, naics_code, year, quarter)
);

-- Geocode outcome for a listing. One row per listing.
CREATE TABLE practice_location (
  listing_id      uuid PRIMARY KEY REFERENCES listing(id) ON DELETE CASCADE,
  address_hash    text NOT NULL,
  point           geometry(Point, 4269),
  tract_geoid     text,
  county_geoid    text,
  place_geoid     text,
  zcta_geoid      text,
  cbsa_geoid      text,
  geo_precision   text NOT NULL CHECK (geo_precision IN ('rooftop','tract','zcta','place','county')),
  geocoded_at     timestamptz NOT NULL,
  geocoder_vintage text NOT NULL
);
CREATE INDEX practice_location_point_gix ON practice_location USING gist (point);

-- Which tracts fall in a listing's drive-time bands, and by how much.
CREATE TABLE practice_catchment (
  listing_id   uuid NOT NULL REFERENCES listing(id) ON DELETE CASCADE,
  band         text NOT NULL CHECK (band IN ('drive_10','drive_20')),
  geo_id       text NOT NULL,
  summary_level char(3) NOT NULL DEFAULT '140',
  vintage      text NOT NULL,
  overlap_frac numeric(6,5) NOT NULL CHECK (overlap_frac > 0 AND overlap_frac <= 1),
  method       text NOT NULL,            -- 'euclidean_buffer_v1' | 'isochrone_v2'
  PRIMARY KEY (listing_id, band, geo_id, vintage)
);

-- The only table the web app reads for market figures.
CREATE TABLE market_metric (
  listing_id     uuid NOT NULL REFERENCES listing(id) ON DELETE CASCADE,
  band           text NOT NULL,
  metric_key     text NOT NULL,          -- 'population' | 'median_hh_income' | 'opportunity_score' | ...
  vintage        text NOT NULL,
  value_num      numeric,
  value_text     text,
  unit           text NOT NULL,          -- 'count' | 'usd' | 'pct' | 'ratio' | 'score'
  is_derived     boolean NOT NULL DEFAULT false,
  formula_version text,
  moe            numeric,
  suppressed     boolean NOT NULL DEFAULT false,
  suppress_reason text,
  source_dataset text NOT NULL REFERENCES dataset_registry(dataset_key),
  computed_at    timestamptz NOT NULL,
  PRIMARY KEY (listing_id, band, metric_key, vintage)
);
CREATE INDEX market_metric_lookup_idx ON market_metric (listing_id, band, vintage);

-- Provenance FK, added once dataset_registry exists.
ALTER TABLE ingest_run
  ADD CONSTRAINT ingest_run_dataset_fk
  FOREIGN KEY (dataset_key) REFERENCES dataset_registry(dataset_key);

-- Which vintage the app is allowed to read. Flipped only after QA.
CREATE TABLE active_vintage (
  dataset_key text PRIMARY KEY REFERENCES dataset_registry(dataset_key),
  vintage     text NOT NULL,
  activated_at timestamptz NOT NULL,
  activated_by text NOT NULL
);

14. Data quality and suppression

  • MOE threshold. Suppress any ACS value whose coefficient of variation — (moe / 1.645) / estimate — exceeds 0.30. Set suppressed = true with reason 'high_moe' rather than deleting the row.
  • Aggregating MOEs. For summed counts, the combined MOE is the square root of the sum of squared component MOEs. Apply the same CV test to the aggregate.
  • Medians never sum. A catchment median is a household-weighted average of tract medians and must carry formula_version and an "approximate" qualifier in the UI.
  • CBP noise flags. Store the Census flag verbatim; treat any noise-flagged establishment count as an estimate and suppress employment or payroll where Census suppressed it.
  • Vintage labeling. Every figure rendered in the product shows its dataset and vintage. Two figures from different vintages must never appear in the same computed ratio.
