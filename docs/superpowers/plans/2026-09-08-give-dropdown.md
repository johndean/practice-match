# Give Dropdown Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Practice Match header's "Give" button the VIN Foundation site's Give control — a navy-on-hover pill with a chevron, a light-blue underline beneath it while it is hovered or open, and a white panel with a thin navy border listing Annual Fund, Cor Group, Legacy Giving and the Dr. Sophia Yin Memorial Fund — reproduced from measurements taken on https://vinfoundation.org/ rather than composed from this design's own tokens.

**Architecture:** One new ruled amendment family, **A14**, five literal `find`/`replace` edits on `docs/design-reference/design_handoff_practice_match_v3/Practice Match V3.dc.html` — four in its `<script data-dc-script>` block, one in its template. The design's Give button is a **single** unconditional `<button>` at V3:104, outside both the `signedIn` and `signedOut` blocks, so it renders in the header of **every** approved state; A14 replaces it with a positioned wrapper carrying a trigger, an underline element and an `sc-if` panel of four `<a>`s. The amendments are applied by `npm run gen:design`; `logic.js` is re-ported and `App.vue`/`pseudo.css` regenerated by `npm run gen:app`. Because the header is on all 43 states, **every** visual baseline and **every** DOM snapshot regenerates from the amended design in the same run, and `frontend/tests/baseline-manifest.json`'s thirteen frozen hashes are re-pinned under this ruling exactly as A6 (the launch removal) re-pinned them — the third time that manifest is re-based by a ruled design change, and the only legitimate reason for it to move.

**Tech Stack:** Vue 3 + TypeScript 6 · Vitest 3 (jsdom for `logic.test.ts`) · Playwright 1.63 (`reference` + `app` projects, `maxDiffPixels: 0`) · the D15 amendment engine (`frontend/tests/design-amendments.ts`, `frontend/scripts/apply-amendments.ts`, `frontend/scripts/convert-dc.mjs`).

**Branch:** worktree `feat/give-dropdown` cut from `main` **after** `feat/metro-dropdown` (family A13) merges — see *Sequencing against A13* below. Nothing here touches the backend.

### The two facts that cannot be reproduced from the bundle

1. **Montserrat is not loaded anywhere in Practice Match.** `frontend/index.html` links only `/ds/colors_and_type.css`, `/ds/preview/_preview.css`, `/ds/ui_kits/vin/kit.css`; `colors_and_type.css` declares four `@font-face`s, all **ProximaNova** (300 Light, 400 Reg, 500 Sbold, 800 Bold), and the design's own `--rf-display` / `--rf-serif` both resolve to `'ProximaNova', Arial, Helvetica, sans-serif`. `grep -rIn Montserrat` over the repository returns nothing. The design's `<helmet>` *preconnects* to `fonts.googleapis.com` (V3:16–17) but loads no Google stylesheet, and `extractTemplate()` strips `<helmet>` before conversion, so nothing reaches either target. **Weight 600 does not exist in ProximaNova either** — the ladder is 300/400/500/800. → **Q1, blocking.**
2. **The live navy is `#07386f`; this design's navy token is `#003a70`** (`--vf-navy`, V3:21). The light blue matches exactly — `--vf-accent: #339dde` (V3:22) is the same hex as the live pill. → **Q2.**

## Sequencing against A13 (`docs/superpowers/plans/2026-09-08-metro-dropdown.md`)

A sibling plan, drafted the same day, adds family **A13** — the Browse toolbar's metro `<select>` becomes a trigger-plus-listbox dropdown built from the **design's own** popover pattern (V3:431/523: white panel, `1px solid var(--border-subtle)`, `border-radius: 8px`, `box-shadow: 0 6px 20px rgba(0,58,112,.16)`). A14 is built from the **live site's** style instead, because John's ruling is "match button design pixel-by-pixel" against vinfoundation.org. **The two visual languages are deliberately different and neither is a defect** — flagged as **Q5** in case John wants one of them changed.

**Can they share the open/close mechanics?** Yes, completely, and they should. A13.4 installs `trackMenuDismiss()` — a `pointerdown` (capture) and a `keydown` (capture) listener on `document`, modelled line for line on the design's only global listener, `trackWidth()` (V3:1864–1869) — and A13.5 arms it in `componentDidMount`. A14 **extends those two closures** rather than installing a second pair: two more literals (A14.4, A14.5) that add a Give branch ahead of A13's metro branch. Sharing costs no pixels in either direction:

- A13's markup lives in the Browse toolbar; A14's lives in the header. Neither `find` overlaps the other's, and neither `replace` produces or destroys the other's `find`.
- The shared code is script, not style. A14.4/A14.5 add branches that are inert while `this.state.giveMenu` is falsy, and leave A13's metro branch's behaviour identical (A13's own Escape and outside-click tests stay green unchanged — assert this in Task G1 Step 1).
- They do both re-baseline the Browse screenshots — A13 for the toolbar, A14 for the header on the same images — but baselines are regenerated from the amended design in the same run, so whichever lands second simply regenerates over the first's output.

**Order: A13 first, A14 second.** A13 is the smaller blast radius (Browse states only; the thirteen frozen hashes do not move) and it is already drafted around *creating* `trackMenuDismiss()`. A14 re-bases onto it:

| If A13 has merged (the default this plan is written for) | If A14 must land first |
|---|---|
| A14.4 / A14.5 **extend** A13.4's `down` and `key` closures (Step 4 below) | A14.4 **creates** `trackMenuDismiss()` + the `componentWillUnmount` teardown, A14.5 arms it in `componentDidMount` (the alternative literals in Step 4) — and A13's plan must then re-base A13.4/A13.5 the same way, and re-base its counts from 13/87/64 to 14/92/69 |
| Counts: **fourteen families, 92 entries, 69 rows** | Counts: **thirteen families, 87 entries, 64 rows** |
| Approved states: 43 → 45 (`browse-metro-menu` + `header-give-menu`) | Approved states: 43 → 44 (`header-give-menu`) |

Both orderings cost A14 exactly five literals. The bodies of A14.4/A14.5 are the only difference.

## What the design already has (the evidence this plan is built on)

- **The Give button, V3:104** — one occurrence in the whole file, outside both `<sc-if value="{{ signedOut }}">` and `<sc-if value="{{ signedIn }}">`, so it is in the header of every screen:

  ```html
        <button style="font-family: var(--rf-display); font-size: 14px; font-weight: 500; color: var(--color-white); background: var(--color-blue); border: 0; border-radius: 6px; padding: 10px 20px; cursor: pointer;" style-hover="background: var(--color-navy);">Give</button>
  ```

  It carries **no `onClick`** — it has never done anything. `--color-blue` is `var(--vf-accent)` = **`#339dde`**, so the idle fill is already the live site's; `--color-navy` is `var(--vf-navy)` = `#003a70`, so the hover is 4 hex digits away from the live `#07386f` (Q2).
- **The header's own popover pattern, V3:88–98** — `<div style="position: relative;">` wrapping a trigger `<button onClick="{{ toggleNavMenu }}">` and an `<sc-if value="{{ navMenuOpen }}">` panel positioned `position: absolute; left: 0; top: 46px; z-index: 60;`. A14's wrapper/trigger/`sc-if`/panel shape is this, verbatim in structure.
- **`ref="{{ … }}"` is a supported idiom** — V3:482 (`ref="{{ md.compareMenuRef }}"`), script V3:2137. `convert-dc.mjs` emits `:ref="…"`; Vue accepts function refs.
- **Inline SVG is a supported idiom** — V3:1416 ships `<svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="#339dde" …><circle …></circle><path …></path></svg>`. `parseDocument` runs with `lowerCaseAttributeNames: false`, so `viewBox` survives. **A14 inlines the chevron rather than adding an icon file** — no new asset, `icons.test.ts` untouched, and the glyph is exactly Font Awesome's rather than an approximation.
- **`style-hover` is the only pseudo the design uses** — `grep -o '\sstyle-([a-z-]+)='` over V3 returns `hover`, 42 times. `style-focus` would be an untested path on the reference runtime, so A14 uses **real focus** (the browser's own ring, exactly as vinfoundation.org does) and never a custom focus style.
- **`{{ … }}` state can be a *new* key with no state declaration.** `!!s.giveMenu` is `false` before anything sets it, so A14 needs no edit to the initial state object — the same trick A13 uses for `marketMenu`.
- **What the design has nowhere:** any keyboard handler, any Escape handler, any outside-click dismissal, any `document.addEventListener`. A13 introduces the first two; A14 extends them and adds Arrow/Home/End focus movement inside the menu. → **Q3**.
