# Browse V3 and Mobile — Design

**Status:** approved by John Dean 2026-09-06 ("the V3 Rev 2 bundle implementation should be done before the Census plan and the two map-engine plans"). Sub-project "Browse V3". Runs now, in its own worktree, in parallel with Wave 2a's backend tasks; merges to `main` before the Census, Map-engines and Google plans start.

**Source of truth:** the design handoff bundle *Practice Match V3, Rev 2* (John's Claude Design export, delivered 2026-09-06), landed in the repo as `docs/design-reference/design_handoff_practice_match_v3/`. `Practice Match V3.dc.html` is the authority for every pixel, value and word of copy. The bundle's own `README.md` (10 tasks), `CHANGE_LOG.md` (C1–C14), `DEAD_CODE_CHECKLIST.md` and `FILE_INDEX.md` are the requirements; this spec records how they join the programme and the decisions the bundle could not make.

## 1. What changes for the member

Browse Practices becomes one screen. The Listings / Market Data toggle is gone. The map, with market data shaded over the communities it covers, sits on the left; the results rail with nine practice cards sits on the right. On the map: a layer select with colour-ramp chips, three named palettes, a Compare panel (six-row bar chart), a Layers drawer with a count pill, one merged legend-and-insight card, persistent practice callouts that pan into view, and a single dashed 16 km drive-time ring. On mobile, the Map tab shows the same map; a navy **Market data** button opens a full-height sheet (Shading, ramp and sources, Compare against, Datasets, What this means, Basemap) with every tap target at 44 px or more. The List tab and the detail screen do not change.

Nothing about accounts, applications or e-mail is in this sub-project (Wave 2a). Nothing about the real Census API is in it either (Sub-project 3): the market data on the V3 screens is the design's fixture data, exactly as on qa.foundation.vin today.

## 2. Scope

**In:** the bundle's ten tasks — land the reference bundle; repoint the generator and the reference server; extend the map engine (rectangles on a shared canvas renderer, tooltip specs, `panInside`, no scale control on the market map); port `MarketMapView.vue` from `MarketMapV3.jsx`; the seven new icons; regenerate `App.vue`/`logic.js`/`app.setup.js`/`pseudo.css`; the router's `tab` query becomes a no-op; the test screen list and baselines; the mobile port (Task 9); the dead-code sweep (Task 10) — plus the cross-plan deltas in §6 and a QA verification and hand-back.

**Out:** the real Census-backed market data API and its `dataset_registry` (Census plan); the Google map engine and the Admin engine switch (Map-engines and Google plans); removal of the prototype jump bar, demo credentials and access-state shortcuts (Wave 2a Task I8, see D2); any change to production, which stays in Coming Soon mode.

## 3. Architecture

The surgical change is not hand-editing `App.vue`. `frontend/src/App.vue`, `frontend/src/logic.js` and `frontend/src/app.setup.js` are **generated** from the design file by `frontend/scripts/convert-dc.mjs` (committed at `c00bc37`; the bundle's "confirm it is committed" precondition is already satisfied — verified against `main` at 47281cb). The work is: land the bundle → repoint `gen:app` and the reference server → regenerate → close the gaps the generator cannot cover (map-engine primitives, the hand-written `MarketMapView.vue`, the router, the screen list, the icons, the mobile sheet's hand-written parts) → sweep dead code, one file per commit.

## 4. Decisions

- **D1 — Sequencing (John, 2026-09-06).** Browse V3 runs now in worktree `feat/browse-v3` from `main`, in parallel with Wave 2a's backend tasks (I4–I6, which touch no frontend file). It merges to `main` first, under the standing condition (production stays Coming Soon; QA remains the working marketplace). It precedes the Census plan and both map-engine plans. Wave 2a rebases onto `main` before its frontend tasks I7/I8.
- **D2 — The generator stays the single source; I8 stops hand-editing `App.vue`.** The launch-removal list (jump bar, demo credentials, access-state shortcuts, `startScreen`/`startViewport`) is executed by a `--launch` mode of `convert-dc.mjs` that strips those blocks during conversion, so `npm run gen:app` reproduces the launch build and `frontend/tests/app-generated.test.ts` stays honest. The identity plan's Task I8 is amended to this design (§6). Until I8 lands, the prototype scaffolding remains, exactly as the bundle's README §8 expects.
- **D3 — Permissions on the merged Browse screen.** The screen is gated by `page.browse`; the market-data shading, layer menu, Compare and Layers drawer on it are gated by `market.read` (honouring `MARKET_DATA_PUBLIC`: when false, anonymous and applicant visitors see the map and results without shading and a sign-in prompt in the market column). The identity plan's Task I7 `permFor()` loses its `browseMode` key (§6).
- **D4 — Map-engines follows V3.** Map-engines Task M5 rebases onto V3's `engine.ts`/`MarketMapView.vue` shape and drops its `ListingsMap.vue` edit (the file no longer exists). Its e2e URLs `/browse?tab=market` keep working as a no-op but its comments are corrected.
- **D5 — Census follows the approved design's rendering and copy.** The Census plan's layer-rendering table is rewritten against V3 (community mosaic shading per layer, one dashed 16 km ring); the economic layer is labelled **"Average Practice Payroll" / "Avg. payroll per practice"** everywhere the API and the UI meet; V3's client-side shading is called **community mosaic shading** in every document so it is not confused with the Census plan's later tract-level tile pipeline (which keeps the word choropleth); the Census plan's migrations start at `017` (identity `010`–`015`, Seed Listings `016`) — amended 2026-09-07: this read `015` before the I5 fix round gave identity `015` and the Seed Listings plan took `016`.
- **D6 — Baselines (re-amended 2026-09-07, option B — John: "keep the V2 header and do not restyle header or fonts").** The display typography is V2's. V7's review established that the V3 bundle deliberately dropped `text-transform: uppercase` and the positive letter-spacing on every display-size heading (26 of 26; micro labels kept theirs) and restyled `{{ resultHeadline }}` from a 19 px display heading to a 13 px micro-label; the option-A default (accept V3's headings) that V9 applied is **withdrawn**. Task V13 restores V2's typography in the design reference itself through a local design amendment (D15, A1): every V3 element paired with a V2 element by its `(tag, text)` key takes V2's `text-transform` and `letter-spacing` values wherever they differ (edited in place — 24 elements, measured 2026-09-07: 22 display headings incl. `{{ md.mdHeadline }}`, which V2 also carries; the key-fact values `{{ m.v }}`, which V2 sets uppercase `.005em`; and `{{ resultHeadline }}`, which takes V2's whole style string); elements whose two declarations already equal V2's (every micro label) are untouched; unpaired V3-only elements (`{{ c.value }}`) are untouched; `<p>` body copy and the price figures pair but V2 did not uppercase them, so nothing changes there. The site `<header>` block is byte-identical between V2 and V3 (5,489 bytes, same hash) — nothing to restore there. Every state is then regenerated from the amended reference at zero tolerance, and the thirteen non-Browse screens are compared against the V1-era manifest (`git show b493cb5:frontend/tests/baseline-manifest.json`, the V2 hashes): where they match, the byte-identical rule of Global Constraint (f) is **restored** with evidence; any screen that does not match is listed with its residual diff for John. The DOM oracle stays the secondary proof.
- **D7 — Tolerance is never relaxed.** `tests/playwright.config.ts` stays at zero; a failure is the change being wrong, not the gate being strict.
- **D8 — Dead-code order.** Deletions happen only after Task 9 is green, one file per commit, each verified by `grep` (no remaining references) and a green frontend gate.
- **D10 — Vue-only conversion (John, 2026-09-06: "convert to vue.js zero-gaps zero-regression").** The app stays Vue 3. `MarketMapV3.jsx` and every other React file in the bundle are reference material to port into Vue (`MarketMapView.vue`, the generated `App.vue`/`logic.js`); nothing React is imported or shipped, and a test asserts it (no `react`/`.jsx` import under `frontend/src/`, no React runtime marker in `frontend/dist/_app/`). The generator remains the only path from the design file to Vue.
- **D11 — Zero regression.** Every existing test keeps passing; the test count only grows except where a task explicitly deletes a test with the dead code it covered. The thirteen non-Browse screens are hashed before Task V1 (a committed manifest of their baseline PNG SHA-256s) as a leak detector through V7; because the V3 design changes their heading typography (D6, option A), the manifest is regenerated from the V3 baselines in V9 and compared byte for byte after V10 and every V11 deletion; the DOM oracle and smoke suites stay green at each of those points; the backend suite runs once at the end to prove no backend file changed. "Zero gaps" means every acceptance criterion in the bundle's README, every CHANGE_LOG entry C1–C14, every DEAD_CODE_CHECKLIST rule and every FILE_INDEX entry appears in exactly one plan task with the test that proves it, and the plan carries a coverage appendix mapping each item to its task and test. **Re-amended 2026-09-07 (option B):** after Task V13 the thirteen are compared against the V1-era manifest (V2's hashes); matching screens restore the byte-identical rule, and the manifest committed after V13 carries those hashes; the V9-era manifest remains the leak detector only for the interval V9–V12.
- **D12 — Two names the bundle leaves undecided (controller defaults, 2026-09-06).** The Playwright state `browse-market-layers-closed` is renamed `browse-layers-open` (amended 2026-09-07: under V3 the drawer is closed by default and that click opens it, so the state shows the drawer open — the earlier `-closed` name was wrong); `convert-dc.mjs`'s `AustinMap: 'ListingsMap'` grammar entry is deleted in the last V11 commit, with its own grep gate, once `ListingsMap.vue` is gone — a dead mapping is dead code; its `MarketMap: 'MarketMapView'` entry follows in its own commit (added 2026-09-07, final review M4: V3's design file contains zero occurrences of the token `MarketMap`, and the V2 folder is an oracle to render, not to convert, so the same argument applies).
- **D13 — Snapshot oracles stay git-ignored (repo policy, pre-flight B2).** `frontend/tests/visual.spec.ts-snapshots/` and `frontend/tests/dom-snapshots/` are regenerated from the design reference in the same run that compares them; the unchanged-screen hash manifest is a within-worktree leak detector regenerated from `main`'s V2 reference before Task V1, never a committed oracle, and never re-run to make a mismatch disappear.
- **D14 — Two engine and contract details settled before execution (pre-flight B3, B4, §3.6).** The drive-time ring is a new engine primitive `ring(center, radiusM, {color, weight, dashArray, fill:false}, group)`; `CircleStyle`/`circle()` are untouched. The V3 reference keeps a vestigial `isBrowse: false` (README §7); the ported `logic.js` carries exactly one occurrence, pinned as a fact until the design drops it. README §5's requirement that "disabled by the user" and "blocked by licence" stay distinguishable when the real API lands is recorded as a Census-plan amendment (`/api/layers` carries `state: disabled | blocked`).
- **D9 — Line numbers in the bundle are advisory.** The bundle's file:line citations run one to three lines high against the live tree; implementers re-grep for the cited symbol before editing.

- **D15 — Local design amendments (mechanism, 2026-09-07).** John owns the design; when he rules a change to it before a re-issued bundle exists, the ruling is applied to the reference file itself so that the generator, the reference server, the baselines and the DOM oracle all see the same design. Mechanism: the pristine Rev 2 file is kept byte-for-byte as `docs/design-reference/design_handoff_practice_match_v3/Practice Match V3.rev2.dc.html`; `Practice Match V3.dc.html` (the file every consumer reads) is the pristine file plus exactly the ruled edits; `frontend/tests/design-amendments.ts` is the single machine-readable list of amendments (`{ id, ruling, date, find, replace, count }`, or a derivation function for rule-based sets) and `frontend/tests/design-amendments.test.ts` proves `apply(pristine, AMENDMENTS) === amended` byte for byte and that every `find` occurs exactly `count` times in the pristine file; `docs/design-reference/design_handoff_practice_match_v3/LOCAL_AMENDMENTS.md` is the human-readable twin (one entry per amendment, John's words, date), and a test pins that every amendment id appears in it. Amendments retire when a re-issued bundle carries them (the test then asserts an empty list against the new pristine file). Nothing else in the bundle is edited.
- **D16 — A1: V2 typography (John, 2026-09-07: "keep the V2 header and do not restyle header or fonts").** See D6. V2's rule, measured: uppercase display headings carry `letter-spacing: .02em` at 19–22 px and `.005em` at 24 px and above; `{{ resultHeadline }}`'s V2 style is `font-family: var(--rf-display); font-size: 19px; font-weight: 800; letter-spacing: .02em; text-transform: uppercase; color: var(--color-navy); line-height: 1.2;`. Task V13. *Corrected 2026-09-07 after V13's first attempt stopped on its own count check: `{{ m.v }}` is restored (V2 had it uppercase), `{{ md.mdHeadline }}` is paired, and the derivation edits values in place so no reorder-only amendments arise; the set is 24.*
- **D17 — A2: the mobile practice card opens the detail (John, 2026-09-07: "resolve this").** Root cause (V9 review §5, re-confirmed): the mobile card's `onClick="{{ p.open }}"` (V3:1341) calls `open: () => this.setState({ browseSel: p.id, activeId: p.id })`, and no markup binds `browseSel` since C13 removed the peek card — so the tap only highlights a pin. V2's card `open` navigated to the detail; V3's desktop card goes to the docked panel and its pins open the detail on the second tap (C13). The amendment changes that one handler in the design's script to `open: () => this.setState({ screen: "detail", detailId: p.id })` — the same navigation C13's second tap performs — leaving `selectMarker` and every other handler untouched. Task V14 (systematic-debugging phases recorded in its report).
- **D18 — A3: "View full market report" → "View full listing" (John, 2026-09-07: "update across the application").** The Insights-tab primary button of the docked panel (V3:705) opens the listing; its label was wrong. One occurrence in the design file; the other tabs' "Open full listing" is not in John's instruction and stays as designed (flagged to John for unification). Task V15.
- **D19 — Plans name deleted files (John, 2026-09-07: "correct the wording as required").** The cross-plan prose names `ListingsMap.vue` explicitly wherever it means that file, inside a clause that says it was **deleted in Browse V3**; the drift test allows the token only on lines carrying that clause instead of forbidding it outright. Task V15.

## 5. Quality gates (Quality and Performance Policy applies)

Every task test-first. Frontend: `npm run typecheck && npm test && npm run build && npx vitest run --coverage` (coverage is only measured with the explicit flag) (hand-written code at 100 % lines, branches, functions, statements; generated files are excluded by the documented convention and covered by the pixel and DOM gates), `npm run test:smoke`, `npm run test:visual` at zero tolerance, the DOM oracle, the bundle budget, `app-generated.test.ts` drift, `reference-server.test.ts`, `convert-dc.test.ts` (extended for the three new constructs). Mobile acceptance at 390×800: shading visible on the Map tab; the key does not overlap the `+`/`−` cluster (`document.elementFromPoint` on each button returns the button); the sheet opens full-height, scrolls, renders all five sections; tapping a selected pin twice reaches the detail screen; every sheet target ≥ 44 px (rows `min-height: 46px`, basemap buttons 46 px, close 44×44 around a 16 px glyph). Backend suite unaffected (`poetry run pytest` still green — no backend file changes). Attribution stays visible on every map (`attributionControl: true`; "Tiles © Esri"). Deployment only to QA (`scripts/deploy.sh QA`, `scripts/verify-deploy.sh QA`); production untouched.

5. **Map-engines and Census plans go stale** until §6 lands; their execution is sequenced after this sub-project by John's ruling, so nothing is built against the old shape.
